## Exact production behavior preservation

- Keep production localization/digit policy in its host wrapper. Chart resources (day axis, previous/next actions, average announcement) are passed through a neutral `LineChartLabels` contract. All axis scaling and touch selection code is relocated from production; it does not calculate spending or FX.
- Production hero guidance remains a host-provided title slot using the existing guidance sheet behavior. Shared hero/default title matches its geometry. Original subtitle, currency typography, footer and chart/navigation behavior remain available.
- Domain/business icon mappings remain in `MasroofIcons` in app. Only existing Lucide outline geometry moves; `docs/licenses/lucide.txt` remains in the repository.
- Move `MasroofLineChartTest` into the module owning its internal axis geometry, retaining all assertions. Extend the existing ui-kit boundary guard to reject app presentation/core/business imports too. No financial/golden assertion is weakened.

## Beta facts and navigation safety

The hero reads `PortfolioTotals.accountRemaining/accountInflow/accountOutflow` directly. These are the precomputed fleet cash position and external inflow/outflow from Finance Core. The mapper never sums accounts or transactions. A missing total remains localized unavailable text; a known zero remains zero; negative values retain their sign. Trend gaps prevent drawing an apparently complete line and are never replaced with spending zero. An unavailable average hides the average line/announcement; the unused numeric reference argument does not create a financial fact.

Home and Transactions requests use saved UI state and a request revision, preserving the existing dashboard detail/period state when returning from editors or recreating the activity. Back from Transactions returns to Home. Review/Settings still use the current guarded editor routes; bottom navigation is hidden there to preserve draft/busy-write guards. BETA and Return remain visible. Full persistent four-tab route ownership and final Settings/Onboarding convergence belong to M10; full screen/detail dashboard parity belongs to M9.

## Native evidence scope

The before fixtures are frozen from base #284 in `app/src/androidTest/.../m2reference/`. They are independent implementations of the original hero, amount typography, shortcuts, navigation and chart renderers, and cannot enter runtime. The eight test cases render Arabic/English × light/dark × phone/wide unfolded-style window, with 1.3 text scale in the wide cases. Each covers populated/unknown/empty/loading/error values, producing 40 before/shared pairs. The native test asserts zero differing pixels and then exercises actual callbacks. Actual dimensions, API, language, font scale and semantics are retained with PNGs by the existing CI collector.

The wide cases change the emulator window to 1800×2400 and require at least 600 dp width; phone cases use 1080×2400. The previous display override is restored in finally. This verifies adaptive window rendering; it is not a claim of physical fold/hinge-device qualification. Caption/state fixtures establish display extraction equivalence; they are not a substitute for all future M9/M10 full-screen data and navigation journeys. Existing Beta loading/error/detail/process-death tests remain part of the same suite.
